# 軌道專屬:QoL 與 UX

> 本檔案與 prompts/goal-base.md 拼接使用。以下僅含本軌道專屬內容。

【終極目標】

把玩家每天會重覆做的操作壓到最低、讓每個狀態一眼可讀:
- 一步到位的日常路徑:開遊戲→領離線→(自動續戰)→看進度/收資源→強化/派遣,主流路徑 ≤ 關鍵點擊數
- 資訊可讀:重要狀態(加速/增益藥水剩餘、連敗回退、離線上限、自動續戰)在該看的地方看得見;數字格式明確
- 可發現性:新玩家能自己找到「這素材去哪打/這東西做什麼/這按鈕幹嘛」;help/教學可重看
- 容錯與安全感:誤觸有救(確認/撤回)、進度有備份(匯出/匯入明顯)、空狀態有指引
- 行動端:點擊目標 ≥44px、safe-area、大字可讀;不產生 console error/效能退化

【檔案地圖 — 本軌道擁有(禁止改數值曲線/美術資產本身)】

- UI 骨架:css/style.css、css/extra.css、js/ui/dom.js(modal/toast/確認)、
  js/ui/screens.js(分頁與重返)、js/ui/main.js(頂欄/導覽)、js/core/save.js(離線結算/匯出匯入頁)
- 各頁 UX:js/ui/kingdom.js(hunt/hunters/equipment/more… 的**互動層**—— 跨頁只透過公開 API 與
  既有 UI 慣例改,不 rewrite 別片區的邏輯)、js/ui/tutorial.js(教學/help 可重看)
- 不碰:render.js drawBattle/drawTown 的繪製層(視覺內容)→ 美術軌道;資料數值 → 數值軌道
- 既有 UX 契約:docs/DESIGN.md §5 UI 慣例(mobile-first/行動端觸控/zh-TW 文案/語彙)、§2 存檔形狀

【backlog 候選方向(以 progress/improvement-log.md 的「QoL 與 UX 軌道 backlog」區段為準,優先未完成項)】

- 素材-需求雙向跳轉(素材總覽點某素材 → 顯示哪區掉落/可做什麼)
  **done when**:點擊任意素材 → 顯示 ≥1 個掉落來源 + 可製作項目,點擊 ≤2 步
- 重要狀態常駐顯示(增益藥水/加速剩餘時間、連敗回退、離線上限在頂欄或獨立橫幅)
  **done when**:≥3 個重要狀態在所有分頁可見(頂欄或獨立橫幅),零點擊即得
- 離線收益結算頁一鍵領取/快速連續領取
  **done when**:離線收益 ≤1 次點擊領取(含確認),連續領取 ≤3 次點擊
- 新手教學/說明可重看(新周目或更多選單內 help 入口)
  **done when**:help 入口在「更多」頁可見,點擊 ≤2 步到達,內容涵蓋所有核心系統
- 存檔匯出/匯入與備份提醒的可發現性
  **done when**:匯出/匯入按鈕在設定頁可見(1× 下 ≥44px),首次遊玩 ≥3 天後彈出備份提醒

【軌道專屬驗證補充】

- 驗證 b:改動的每個觸發路徑實測(含邊界:首次/重複/異常輸入、未解鎖狀態、舊存檔);
  量測改動前後摩擦(點擊數/時間/步驟數)
- 驗證 f:inspect_image 檢查「資訊密度/層級/可讀性/與既有樣式協調」→ 不合格回改;
  不適用(純邏輯 UX)時以互動錄影/步驟序列替代,報告註明

【軌道專屬禁止】

- 禁止:遊戲數值曲線/掉落/難度的改動(數值軌道)、繪製層美術資產(render.js/art 檔 → 美術軌道)、
  存檔 schema 新增欄位(如需新增 → 走 normalize + 遷移契約)、新增隨機性
