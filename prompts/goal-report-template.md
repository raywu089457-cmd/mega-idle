# 共通報告格式(各軌道 prompt 引用)

每輪報告寫入 `progress/improvement-log.md`,最新在上。格式如下,
各軌道在【驗證】段補充軌道專屬項目。

```
### [vN] 軌道:【軌道名】(全局輪次 R・循環 C)
改動:一句話(原子改動群可列 ≤3 項)
為何讓玩家玩更久:具體留存理由(強制書寫)
診斷證據:改動前量測(截圖/模擬表/點擊序列/數字)
實作:檔案清單
驗證(必選項 a/c/d + 軌道專屬 b/e/f):

【必選項】
a) 語法:node --check 全數通過
c) 回歸:核心流程(王國→副本→英雄→裝備→建築→更多→回城待機)通過;
   受影響既有功能逐一確認;零 console error/unhandledrejection
d) 實機:瀏覽器實測(行動 390×844 + 桌機 1280×800),
   零 console error,reducedMotion 路徑

【軌道專屬項】
b) 邏輯/數值:改動的每個觸發路徑實測(含邊界)
   - 數值輪:同一支模擬前後對照表 + 硬斷言清單
   - 美術輪:像素精確斷言 + reducedMotion 路徑
   - QoL 輪:改動前後摩擦量測(點擊序列/時間/步驟數)
e) 截圖:至少 2 張存 progress/(命名含 vN;before/after 或流程步驟)
f) 視覺/審美閘門(美術/QoL 輪強制):
   - 美術輪:4× 放大 + inspect_image 檢查 + 並排對照
   - QoL 輪:inspect_image 檢查資訊密度/層級/可讀性
   - 數值輪:模擬表截圖或 UI 截圖
   - inspect_image 不可用時:降級為截圖自檢+DOM 探針,報告註明降級

風險與回滾點:...
```

## 軌道專屬驗證補充

| 軌道 | b) 項額外要求 | f) 項額外要求 |
|------|--------------|--------------|
| 數值平衡 | 同支模擬前後對照表 + 存檔相容測試 | 模擬表截圖 |
| 村莊美術 | 像素採樣 + rm 定幀 hash + 確定性 | 4× 放大 + 並排 + ART-RULES 比對 |
| 戰鬥美術 | 逐幀/技能觸發 + rm 定幀 + 60fps | 4× 放大 + 逐幀 + 語彙協調 |
| QoL 與 UX | 互動實測 + 邊界(首次/重複/異常) | 資訊密度/層級/可讀性 |

## 版本慣例

改動 → index.html 全部 ?v= 快取 +1。
**不硬編碼當前版本號**:以 improvement-log.md 最新 [vN] 的 N 為基準,+1 後寫入。

## 修正輪偵測

若 `progress/round-<R>-feedback.md` 存在 → 本輪為修正輪:
- 讀 feedback 的修正清單,只修列出的問題,不換題/不擴大範圍
- 報告標註「修正輪(第 N 次)」
- changelog.js 和 index.html 快取不 +1(沿用原 vN)
